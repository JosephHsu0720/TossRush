# Editor prototype 執行目標

依據《20 Second Game Jam 2026｜Unity 開發執行計畫》v0.1，並依本次要求將交付範圍限定為 Editor 可玩版本。專案名稱沿用 TossRush。

日期：2026-11-11。

| 目標 | 實作內容 | 驗收方式 |
|---|---|---|
| 一局完整可玩 | 開始、20 秒主計時、結算、最高分、Restart | Play Mode 完整倒數與重玩測試 |
| 固定位置第一人稱投擲 | 滑鼠瞄準、左鍵固定力度、Rigidbody、拋物線預覽 | 實際物理飛行與紙團第一投測試 |
| 四個舞台 | 房間／垃圾桶、側風／籃框、移動／洞口、個人房間角落 | 逐場驗證命中後切換 |
| 正確命中判定 | 連續跨平面檢查，含物品半徑、進入方向、舞台 token | 正面／反向／洞外／過期投擲物測試 |
| 有限物件數量 | 三種物品各預建 16 個，共 48 個；兩個紙團關卡共用同一池；池滿即拒絕投擲 | 100 次連續發射與重設檢查 |
| 易於修改 | StageData、Stage／Target／Projectile／Player／HUD Prefab | Inspector、資產引用與場景檢查 |
| 基本視聽回饋 | 統一卡通 Shader、UI Pulse Shader、命中音、得分提示、末五秒警示、遮罩轉場 | Play Mode 畫面、Console 與材質檢查 |
| 來源可追溯且資源精簡 | Kenney CC0 素材、保留三份原始授權，移除未使用範本 | 素材清單與引用檢查 |

## 本版設計細節

- 舞台固定順序，命中後切換；未命中不自動切換，允許持續重投。0.3 秒遮罩轉場期間不能投擲／得分，主倒數持續。
- 未命中可再次投擲；舊舞台的投擲物在切換時回收。
- 紙團與籃球必須從上方跨過開口；沙包必須從洞口前方穿越。物品中心必須留出整個碰撞半徑，擦過邊緣不算得分。
- 每種物品共用發射／加速度／生命週期程式；重力由 StageData 控制；每次進入舞台抽取目標水平／深度位置、側風方向與風速，當次投擲固定使用該舞台的風速。質量與材質由獨立物理設定資產控制。
- 籃球已調成較高弧線；側風隨機向左或向右，HUD 顯示方向與風速，需要玩家迎風修正。園遊會需預判洞口移動，拋物線不會自動追蹤目標。
- 更改 StageData 的 `targetRadius` 會於下一次進入 Play Mode 時同步縮放目標幾何。
- UI 目前以英文呈現，使用包內 CC0 字型，沒有匯入大型 CJK 字型。
- 原型使用簡單幾何構成桶、籃框、洞口與舞台；家具、按鈕、字型、音效使用既有素材。

## 後續保留給人工試玩的驗收

- 三種投擲的手感、得分難度與公平性。
- 移動洞口速度、側風強度是否適合 20 秒節奏。
- 是否需要更明顯的環境美術、沙包造型與額外回饋。

這些體驗判斷不以自動化測試代替。WebGL 建置、瀏覽器焦點、不同裝置與 itch.io 發布不在本輪執行範圍。
